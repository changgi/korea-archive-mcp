# 조선 1차사료 발굴 스킬

한강 강배 조사(1485~1986, 34건 전수목록·규장각 원문 6종·비변사등록 601건)에서 검증된 절차다.
핵심 전제 하나만 기억하면 된다.

> **이 사이트들은 "검색"으로 열리지 않는다. "구조로 진입"해야 열린다.**

도서관에 비유하면, 구글은 책등(제목)을 훑는 사서다. 한국사DB·규장각은 책등이 아니라
**서고 배치도**를 알아야 하는 곳이다. 『만기요람』을 검색해서 총론만 읽고 나오는 것은
백과사전에서 표제어만 읽고 항목 본문을 안 읽는 것과 같다 — 실제로 이 조사에서
**시공 시방서·배정 산식·과적 형량표가 전부 첫날 열었던 그 편(篇) 안에** 있었는데 놓쳤다.

---

## 0. 실행 순서 (이 순서를 지킬 것)

| 단계 | 하는 일 | 실패 시 |
|---|---|---|
| 1 | **어휘 정찰** — 핵심어를 한자·국역어 양쪽으로 전 DB 건수 조회 | 건수 0이면 어휘 자체가 당대어가 아님 → 유의어 재수립 |
| 2 | **분포 판독** — 어느 DB에 몰려 있는지로 사료 성격 판정 | 법전 0·등록 다수 = "법전에 없는 제도" (중요 신호) |
| 3 | **형제 조 전수 확인** — 히트한 조(條)의 **같은 편(篇) 안 모든 조**를 그 자리에서 훑기 | 미루면 반드시 놓친다 (아래 §3) |
| 4 | **원문 확보** — 규장각 이미지 / DB 한문 원문 / 국역 註 | 한문 미노출이면 §5의 2층위 고지 적용 |
| 5 | **인용 고정** — levelId 기반 영구 URL + 재현 쿼리 기록 | URL 유효성 전수 검증 (§6) |

## 1. 접근 경로 — 전부 POST다 (GET은 404 / 무시됨)

전체 파라미터·응답 파싱·파이썬 최소 구현은 **`references/endpoints.md`** 를 열 것.
요약만 옮기면:

| 대상 | 엔드포인트 | 핵심 파라미터 |
|---|---|---|
| 한국사DB 통합 | `POST db.history.go.kr/search/searchTotalResult.do` | `totalWord`, `chinessChar=on` |
| 조선시대 하위DB | `POST db.history.go.kr/joseon/search/searchResultList.do` | `searchItemId` = `bb`(비변사등록) / `jlaw`(법령) |
| 승정원일기 | `POST sjw.history.go.kr/search/searchResultList.do` | `searchTerm` |
| 조선왕조실록 | `POST sillok.history.go.kr/search/inspectionMonthList.do` | `topSearchWord` |
| 규장각 목록 | `POST kyudb.snu.ac.kr/search/search.do` | `totalSearchString`, `searchArea=10` |
| 규장각 **해제** | 같은 URL | `searchArea=20` ← **절목·사목류는 이쪽에만 잡힌다** |

**주의 3가지**
- `chinessChar=on` 을 빼면 한자 색인이 죽는다. 비변사등록 `添載` 는 이 옵션으로 **961건**이 나온다.
- 규장각은 `web_fetch` 계열 도구가 차단되는 경우가 있으나 **urllib 직접 요청은 200 OK**. 도구 실패를 자료 부재로 읽지 말 것.
- 인용 URL은 검색 URL이 아니라 **`db.history.go.kr/id/<levelId>`** 형태로 고정한다. POST 기반 검색 URL은 GET 재현이 안 된다.

## 2. 규장각 원문 이미지 — 2단 호출

목록에서 `fn_originalImg('item_cd','GK05485_00','','')` 같은 호출부를 뽑아 `book_cd`를 얻고,
`POST /pf01/rendererImg.do` → `/ImageServlet.do?imgFileNm=...&path=/data01/stream/{item_cd}/IMG/{book_cd}/...` 로 내려받는다.

`item_cd`는 자료 성격별로 갈린다 — **圖本=ART / 잡류=ETC / 등록=DRR / 사목=FND / 정책서=POL**.
이걸 모르면 경로가 안 잡힌다. (검증된 5종 대조표는 `references/endpoints.md`)

## 3. 철칙 — 편·조 구조 사료는 형제 조를 전수 확인한다

『경국대전』·『속대전』·『만기요람』·『육전조례』는 **편(篇) 안에 조(條)가 나열된** 구조다.
검색은 한 조(條)만 물어다 준다. **그 조의 형제들이 진짜다.**

> 병원 전자차트에 비유하면: 검색은 "혈압" 항목 하나만 띄운다. 그런데 같은 진료 회차의
> 체온·투약·경과기록을 안 열면 환자 상태를 모른다. 사료도 똑같다.

- **반드시 검색 결과를 받은 그 자리에서** 형제 조를 훑는다. 미루면 "이미 답을 얻었다"고
  착각한 채 다음 단계로 넘어간다 (실제 발생 사례).
- 자매 사료 대조도 함께: 같은 사항을 『만기요람』과 『육전조례』가 **다르게 적는다**
  (예: 領將 10인 vs 13인). 불일치 자체가 발견이다.

## 4. 분포를 지표로 쓸 때의 함정

검색 건수를 "중요도"로 읽으면 안 된다. 비변사등록 601건 중 **492건이 座目(참석자 명단)**이었고
실질 기사는 109건이었다. **건수는 반드시 표본 열람으로 성격을 확인한 뒤 인용한다.**

반대로 **분포의 공백은 강력한 증거**다. `執籌`가 법령DB 조문 0건인데 등록·일기에 수십 건이면,
그것은 "자료가 없다"가 아니라 **"법전 밖에서 작동한 제도"**라는 발견이다.

## 5. 인용 고지 — 반드시 2층위로 나눌 것

| 층위 | 대상 | 인용 방식 |
|---|---|---|
| **ⓐ 원문 직접** | 법전·편람류(경국대전~육전조례·만기요람) — 한문 원문이 DB에 노출 | 원문 그대로 인용 가능. 단 "표점은 DB 형태, 교감본 미대조" 명시 |
| **ⓑ 역구성** | 등록·일기류(비변사등록·승정원일기) — 국역만 노출 | 한문 표기는 **역구성이며 학술 인용 불가**로 명시 |

"전부 시역(試譯)입니다"라고 뭉뚱그리면 **원문을 직접 옮긴 부분까지 불필요하게 평가절하된다.**
※ 한자 색인은 존재하는데 원문 텍스트만 미노출인 경우가 있다 → 소장기관에 원문 열람 경로를 문의하면 풀린다.

## 6. 마감 전 검증 3종

1. **levelId 유효성 전수** — 항목이 존재해도 **본문이 비공개**인 경우가 있다.
   "도달하지 못했다"와 "공개되지 않았다"는 다르고, 후자는 재시도로 해결되지 않는다.
2. **외부 URL 전수** — HTML 엔티티(`&amp;`)를 그대로 조회하면 오탐이 난다. 해제 후 재검.
   `202 Accepted`는 봇 차단이 아니라 비동기 응답이다.
3. **번역 층위 표시 누락** 검사.

## 7. 산출 형식 (필수 열)

발굴 결과는 반드시 다음 열을 갖춘 표로 보고한다.

`자료명 · 청구기호/levelId · 연대 · 소장처 · 인용URL · 원문제공여부(원문/국역/미공개) · 권리등급 · 재현쿼리`

**재현쿼리 열을 비우지 말 것.** 이 조사의 재현 가능성을 담보하는 것은 결과 목록이 아니라
**어떻게 도달했는가**이며, 실패한 시도와 그 원인까지 적어야 다음 사람이 헛수고하지 않는다.

## MCP 도구가 붙어 있으면

korea-archive MCP에 이 스킬의 `mcp/` 도구가 등록되어 있으면 다음 순서로 쓴다.

`khdb_search`(어휘 정찰) → `khdb_sibling_scan`(형제 조 전수) → `kyujanggak_search`(원문 소재)
→ `kyujanggak_image`(도판) → `khdb_verify_ids`(마감 검증)

도구가 없으면 `references/endpoints.md`의 파이썬 스니펫을 그대로 실행하면 된다. 결과는 동일하다.

## 함께 쓰는 스킬

발굴이 끝나면 **`archive-fullpackage`** 스킬로 넘어간다. 보고서·전시기획·카드뉴스·온톨로지를
한 벌로 만들고, `consistency_check.py`로 산출물 간 정합을 기계 점검한다.
