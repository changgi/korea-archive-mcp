# 규장각 원문 이미지 수집 스킬

2026-08-18에 실제로 내려받아 확정한 절차다. 추측이 아니라 실측이다.

핵심은 한 줄이다.

> **파일명을 조립하지 말 것. 서버가 목록을 준다.**

---

## 1. 4단계 파이프라인

```
① 검색          search.do              →  book_cd  (예: GK15752_00)
② 경로 해석     rendererImg.do         →  실제 item_cd (예: ART)
③ 면 목록       viewImgList.do (JSON)  →  전 면의 정확한 파일명
④ 내려받기      ImageServlet.do        →  JPEG
```

②를 건너뛰고 `item_cd`를 추측하면 조용히 실패한다. ③을 건너뛰고 파일명을 만들면 반드시 실패한다.

전체 파라미터와 실행 코드는 **`references/pipeline.md`**.

## 2. 실행

```bash
python scripts/kyu_fetch.py --search 各船圖本          # ① 자료 찾기
python scripts/kyu_fetch.py --book GK15752_00 --list   # ③ 면 목록 확인
python scripts/kyu_fetch.py --book GK15752_00 -o out/  # ④ 전 면 수집
python scripts/kyu_fetch.py --book GK05485_00 -o out/ --pages 11-14
```

`manifest.json`이 함께 생성된다 — 파일명·해상도·바이트수·**재현 URL**·권리 등급·수집 일시.
이게 있어야 나중에 "이 이미지 어디서 났나"에 답할 수 있다.

## 3. 반드시 알아야 할 함정 4가지

### ① `path`는 디렉터리가 아니라 **파일 전체 경로**다

```
✕  &path=/data01/stream/ART/IMG/GK15752_00/GK15752_00_0001/
✓  &path=/data01/stream/ART/IMG/GK15752_00/GK15752_00_0001/GK15752_00_IL_0001_0001.jpg
```

디렉터리만 넘기면 **HTTP 200 OK에 0바이트**가 돌아온다. 예외도 안 나고 파일도 생긴다.
**조용히 실패하는 종류라 가장 위험하다.** 수집기가 매 면마다 JPEG 매직바이트와 해상도를
확인하는 이유가 이것이다.

### ② 파일명 규칙이 자료마다 다르다 (실측 3종)

| 자료 | 파일명 | 특징 |
|---|---|---|
| 舟橋指南 奎5485 | `GK05485_00IH_0001_0001.jpg` | 밑줄 없음 · 0001부터 |
| 各船圖本 奎15752 | `GK15752_00_IL_0001_0000.jpg` | 밑줄 있음 · **0000부터** |
| 禁營津船謄錄 奎19356 | `GK19356_00_IH_0001_000a.jpg` | **접미 a/b** (앞뒤 면) |

`IH` / `IL` 도 갈리고 시작 번호도 갈린다. **규칙을 찾으려 하지 말고 목록을 받아라.**

### ③ `item_cd`는 추측하지 않아도 된다

요청할 때 리터럴 문자열 `item_cd`를 그대로 넣으면 서버가 `book_cd`로 역산한다.
(규장각 검색 페이지 자신이 `fn_originalImg('item_cd', 'GK07315_00', '', '')` 로 그렇게 보낸다.)
실제 코드는 렌더러 응답의 경로에서 읽는다 — `/data01/stream/**ART**/IMG/...`

> 앞서 만들어 둔 자료에 "item_cd 대조표(ART/ETC/DRR/FND/POL)를 읽어야 한다"고 적었다면
> 그것은 불필요한 단계였다. 대조표는 참고용으로만 두고, 실제로는 ②단계가 알아서 해결한다.

### ④ 해상도는 **자료마다도, 면마다도** 다르다 — 판독 가능성이 여기서 갈린다

| 자료 | 면 | 해상도 | 화소 |
|---|---|---|---|
| 各船圖本 奎15752 | 도판 | 1500×2141 | **3.2MP** |
| 舟橋指南 奎5485 | 본문 펼침면 | 1171×1071 | 1.3MP |
| 舟橋指南 奎5485 | **표지** | 680×1075 | 0.7MP |

같은 책 안에서도 표지 0.7MP, 본문 1.3MP로 갈린다. **1면만 보고 자료 전체를 판정하지 말 것.**
판정은 짧은 변이 아니라 **총 화소**로 한다(펼침면은 가로가 길어 짧은 변만 보면 오판한다).

| 화소 | 판정 |
|---|---|
| 3.0MP 이상 | 잔글씨·주기 판독 여지 있음 |
| 1.2~3.0MP | 도상·큰 글자는 가능, 잔글씨는 불확실 |
| 1.2MP 미만 | 개요 수준. 표지·간지이거나 사본 해상도가 낮은 경우 |

그리고 이것이 핵심이다 —

> **"이 해상도에서는 판독되지 않는다"는 자료의 한계가 아니라 사본의 한계다.**

원본 실사·고해상 촬영 요청으로 풀린다. 어노테이션 범례에 그 구분을 적어야
다음 사람이 헛되이 같은 이미지를 다시 들여다보지 않는다.

## 4. 권리 — 내려받기와 게재는 별개다

규장각 자료의 기본 등급은 **C (소장기관 허가 필요)**다.

| 행위 | 가능 여부 |
|---|---|
| 조사·판독을 위한 내려받기 | 통상 가능 |
| 보고서 내부 참조 | 통상 가능 |
| **전시·출판·SNS 게재** | **별도 허가 범위 확인 필요** |
| 재배포·2차 가공물 배포 | 반드시 사전 협의 |

`manifest.json`에 `rights` 항목이 자동으로 들어간다. **비우지 말 것.**
어노테이션 카드로 넘길 때는 메타 표 권리 행에 `C · 소장기관 협조 취득 후 게재`처럼
**취득 사실까지** 적는다(`record-annotation` 스킬의 검사기가 이걸 본다).

또 하나 — 내려받은 것은 **원본이 아니라 서비스용 사본**이다. 출처 줄에 계보를 적는다:
`규장각 소장 원본 → 공개 뷰어 서비스 이미지 → 본 도판`.

## 5. 예의

국가 연구기관 서버다. 수집기는 기본 **0.5초 간격**으로 요청한다. 병렬로 때리지 말 것.
148면짜리 등록을 받으면 2~3분 걸린다. 그 정도는 기다리는 게 맞다.

## MCP 도구가 붙어 있으면

`kyujanggak_search` → `kyujanggak_pagelist` → `kyujanggak_fetch` → `kyujanggak_manifest`.
설치는 `mcp/README.md` 참조.

## 이어지는 스킬

내려받은 도판은 **`record-annotation`** 스킬로 해설 카드를 만든다.
`manifest.json`의 항목이 카드 메타 표의 식별번호·소재·권리 행으로 그대로 들어간다.
