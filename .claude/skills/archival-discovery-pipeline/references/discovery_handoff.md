# 발굴 스킬과의 연계

`korea-archive-discovery` 플러그인과 이 파이프라인은 **이어 쓰도록 설계되었다.**

## 경계

| | korea-archive-discovery | 이 파이프라인 |
|---|---|---|
| 하는 일 | 자료를 **찾는다** | 찾은 자료를 **연다** |
| 범위 | 5개 소스 검색·쿼리 전략·권리 초판 | 실물 검토·판독·재기술·논문·전파 |
| 산출 | 발굴 목록 표 + HTML 보고서 | 재기술·메타데이터·도판·캐러셀 |
| 끝나는 지점 | **식별자와 URL을 확보한 때** | 논문 논거와 전파물이 나온 때 |

**발굴 스킬이 끝나는 지점에서 이 파이프라인이 시작한다.**

> 발굴 스킬은 「자료가 있다」까지 말하고,
> 이 파이프라인은 「그 안에 무엇이 있다」를 말한다.

---

## 인계 방법

```bash
# 발굴 표(마크다운/CSV/JSON)를 판독 대기열로
python scripts/from_discovery.py <발굴결과> --out <디렉터리>

# MCP 응답을 붙여넣어도 된다
python scripts/from_discovery.py --paste "<nara_search 응답>" --out <디렉터리>

# 우선순위만 보기
python scripts/from_discovery.py <발굴결과> --plan
```

산출: `reading_queue.json` — 판독 전 골격이 채워진 대기열.

## 판독 우선순위 — 무엇부터 열 것인가

발굴 결과가 수십 건이면 순서를 정해야 한다.
**원 기술이 무언가를 숨기고 있다는 신호**를 점수화한다.

| 신호 | 점수 | 뜻 |
|---|---|---|
| 표제에 **「ETC」** | +30 | 가려진 내용이 있다 |
| **「VARIOUS」·「MISCELLANEOUS」** | +25 | 내용을 전혀 알 수 없다 |
| 세미콜론 | +20 | 두 번째 주제가 있다 |
| **당대 표기 지명** | +15 | 표기 확장의 성과 |
| 표제가 4단어 이하 | +12 | 내용 불명 |
| URL 확보 | +8 | 즉시 열람 가능 |
| **권리 D등급** | **-40** | 게재 불가 — 존재만 기록 |

실제 적용 예:

```
★★★ [70] 111-lc-31541  EISENHOWER VISITS KOREA; ETC
         · 「ETC」 — 표제가 가린 내용이 있다
         · 세미콜론 — 두 번째 주제가 있다
```

이 자료를 실제로 열어 보니 「ETC」 뒤에
**대한민국 대통령의 극동사령부 방문**이 있었다.

## MCP 도구를 파이프라인 안에서 쓰기

발굴이 끝난 뒤에도 MCP 도구가 필요한 지점이 있다.

### ① 권리 재판정 — `judge_rights`

발굴 스킬의 권리 등급은 **자동 초판**이다. 실물을 본 뒤 재확인한다.

```
judge_rights(identifier, repository, rg_series, title, date)
```

특히 **D등급(노획 기록)**은 실물을 봤더라도 화면을 게재하지 않는다.

### ② 국내 교차검증 — `koreanwar_search` · `archives_search` · `nedb_search`

**재기술 전에 국내 소장 현황을 확인한다.**
같은 자료가 국내에 한국어 제목과 함께 있을 수 있다.

```
koreanwar_search("<원제 키워드>")     KOREAN WAR ARCHIVES 6·25전쟁 아카이브센터
archives_search("<주제어>")           국가기록원
nedb_search("<사건명>")               한국사DB — 문헌 대조
```

**중복을 피하려는 것이 아니라, 자기 작업이 무엇의 옆에 놓이는지 알기 위해서다.**
국내에 이미 상세 기술이 있다면 그것을 인용하고, 없다면 그 사실을 기록한다.

### ③ 자매편 찾기 — `nara_search` · `tna_adjacent_mine`

판독 중 **ROLL 번호**가 나오면 나머지 릴을 찾는다.

```
슬레이트에 「ROLL 3」이 있다면 → ROLL 1·2를 찾는다
과제번호 「FEC 67」이 있다면   → 같은 과제의 다른 자료를 찾는다
```

```
nara_search("<과제번호>", record_group="111")
tna_adjacent_mine(reference, radius=8)      # 참조코드 인접 순회
```

**ROLL 1·3이 있는데 2가 없다면**, 그 자료를 열람 신청 대상으로 특정할 수 있다.
이것이 온톨로지의 `sibling_of` 관계가 끊긴 지점을 찾는 이유다.

### ④ 재현 쿼리 확보 — `query_bank`

논문과 보고서에 실을 **검증된 쿼리**를 가져온다.

```
query_bank()   # 검증된 발굴 키워드 목록
```

## 왕복 구조

한 방향으로만 흐르지 않는다. **판독 결과가 다시 발굴로 돌아간다.**

```
발굴 스킬                     이 파이프라인
   ↓ 식별자·URL                  ↓
   └──────────────────────────→ 실물 검토·판독
                                   ↓
   ┌──────────────────────────← 새 단서
   ↓                              (ROLL 번호·과제번호·지명·부대)
재검색 (nara_search 등)
   ↓
자매편·계열 자료 추가 발굴
```

### 판독에서 나오는 재검색 단서

| 판독한 것 | 다시 찾을 것 |
|---|---|
| ROLL 3 | ROLL 1·2 |
| 과제번호 FEC 67 | 같은 과제의 다른 릴 |
| 촬영자 SHAYDAK | 같은 촬영자의 다른 자료 |
| 지명 SAISHU | 그 표기로 더 검색 |
| 부대 FE Signal Corps | 같은 부대의 다른 기록 |

**이 왕복이 발굴의 실질이다.** 한 번 검색하고 끝내면 계열이 복원되지 않는다.

## 중복을 피한다

발굴 검색 전략은 **플러그인의 `query_cheatsheet.md`가 정본이다.**
이 파이프라인의 `discovery_queries.md`는 판독 중 재검색이 필요할 때만 참조한다.

| 상황 | 읽을 문서 |
|---|---|
| 처음 자료를 찾을 때 | 플러그인 `references/query_cheatsheet.md` |
| 판독 중 단서가 나와 재검색할 때 | 이 문서의 「왕복 구조」 |
| 0건이 나왔을 때 | 플러그인 SKILL.md 「0건 ≠ 부재」 |
