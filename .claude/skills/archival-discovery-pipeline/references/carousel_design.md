# 캐러셀 설계

발굴 결과를 SNS·전시용 이미지로 만드는 방법.

## 설계 원리 넷

### ① 서사 구조

**정보 나열이 아니라 이야기가 흘러야 한다.**

```
표지(질문)  →  원 기술의 공백  →  데이터  →  화면으로 답함  →  마무리
```

열 장이 하나의 논증을 이룬다. 무작위 배열은 아무도 끝까지 보지 않는다.

### ② 레이아웃 다양성

**같은 틀을 열 번 반복하지 않는다.**
카드마다 구성이 달라야 스크롤이 이어진다.

### ③ 타이포 중심

큰 한글 문장이 화면을 지배하고, 이미지가 그 문장을 뒷받침한다.
이미지가 주인공이 되면 메시지가 흐려진다.

### ④ 색 규약

| 색 | 용도 |
|---|---|
| 금색 | 제목·강조 |
| 청록 | 원 기술(인용) |
| 분홍 | 문제·미확인 |
| 청색 | 수치 |
| 녹색 | 확인된 것 |

---

## 열 장 구성

| 장 | 레이아웃 | 역할 |
|---|---|---|
| 01 | `cover` | 질문형 대제목 · 식별자 |
| 02 | `quote` | 원 기술 인용 + 결정적 문장 |
| 03 | `bars` | 데이터 — 원 기술 분량 vs 실제 |
| 04 | `duo` | 핵심 발견 두 장면 |
| 05 | `full` | 대표 화면 전면 |
| 06 | `split` | 화면 속 문자의 판독 |
| 07 | `full` | 추가 장면 |
| 08 | `table` | 소장 정보 |
| 09 | `rights` | 권리 등급 + 재현 쿼리 |
| 10 | `closing` | 확인/미확인 + 서명 |

**8·9·10장이 이 시리즈를 다른 카드뉴스와 구별한다.**
소장 정보·권리 판정·미확인 목록이 없으면 그냥 예쁜 이미지일 뿐이다.

## 레이아웃별 사양

### cover — 표지

```json
{"type":"cover",
 "era":"1 9 4 8 . 0 4 . 3 0   ·   제 주",
 "title":"표제와 화면이\n다른 필름",
 "sub":"카탈로그는 「MAY DAY」라 적었다",
 "foot_id":"111-ADC-7115 · NAID 20887 · 6분 41초"}
```

`era`는 글자 사이를 띄워 쓴다. 제목은 두세 줄이 적당하다.

### quote — 원 기술 인용

```json
{"type":"quote",
 "lead":"미 국립기록청의\n원래 기술은 이렇습니다",
 "orig":"MAY DAY IN KOREA,\nCHEJU-DO",
 "punch":"그런데 슬레이트는\n4월 30일입니다",
 "note":"메이데이 전날이며,\n화면도 노동절 행사와 맞지 않습니다.",
 "box_h":150}
```

`box_h`는 인용 박스 높이. 원 기술 줄 수에 맞춰 조정한다.

### bars — 데이터

```json
{"type":"bars",
 "head":"같은 도시, 다른 이름",
 "rows":[["Busan (현행)",0,"검색 결과"],
         ["Pusan (당대)",14,"검색 결과"]],
 "unit_fmt":"{}건",
 "tail":"자료가 없는 게 아니라\n검색어가 닿지 않는 것입니다."}
```

최대값이 자동으로 강조된다. `rows`는 3개 이하가 읽기 좋다.

### duo — 2컷 병렬

```json
{"type":"duo",
 "head":"완전 판독된 현수막",
 "pair":[["/path/a.jpg","현수막 근접"],["/path/b.jpg","시가 행진"]],
 "punch":"信託統治決死反對",
 "note":"영문 병기 WE DENOUNCE THE TRUSTEESHIP"}
```

### full — 전면 이미지

```json
{"type":"full","img":"/path/x.jpg",
 "punch":"태극기로 장식된 청사","note":"중앙청 정면과 관중석"}
```

### split — 좌우 분할

```json
{"type":"split",
 "head":"자매편을 구별합니다",
 "img":"/path/x.jpg",
 "items":[["55899","1970.7.26 · SMITH","같은 표제"],
          ["55900","1970.7.24 · CLARK","이틀 차이"]],
 "vcol":[247,183,49],
 "punch":"표제가 같다고\n같은 자료가 아닙니다."}
```

`vcol`은 값 색상(RGB 배열). 생략하면 분홍.

### alert — 강조 박스

```json
{"type":"alert",
 "lead":"그런데",
 "head":"가장 결정적인 필름은\n열리지 않습니다",
 "box":"1945.9.9 조선총독부 항복조인식\nNAID 19044 — 카탈로그에만 존재",
 "note":"필름은 있습니다.\n다만 온라인에 공개되지 않았습니다.",
 "box_h":150}
```

적색 테두리 박스. 문제 제기에 쓴다.

### table — 소장 정보

```json
{"type":"table",
 "rows":[["소장처","미국 국립기록청 (NARA)"],
         ["기록군·식별자","RG 111-ADC · NAID 20887"],
         ["분량","6분 41초 · 무성"],
         ["재공개","archive.org (FedFlix)"]],
 "note":"미 연방정부 직무저작물은 저작권이 발생하지 않습니다."}
```

### rights — 권리 등급

```json
{"type":"rights",
 "grade":"B",
 "note":"본 작업은 권리와 게재를 별개로 다룹니다.",
 "query":"SAISHU · KEIJO · PUSAN"}
```

`grade`는 A/B/C/D. 배지 색과 법적 근거가 자동으로 붙는다.
「자동 초판 — 출판 전 인간 최종 확인 필수」도 자동 표기.

### closing — 마무리

```json
{"type":"closing",
 "punch":"검색어를 바꾸면\n찾을 수 있습니다",
 "body":"archive.org/details/111-adc-7115",
 "confirmed":"· 촬영일 확정\n· 표제 불일치 확인",
 "unconfirmed":"· 벽보 판독 실패\n· 인물 비정 안 함"}
```

각 목록은 **4줄까지만** 표시된다. 핵심만 추린다.

## 사양 파일 구조

```json
[{
  "id": "adc7115_jeju",
  "cards": [ ... 열 장 ... ]
}]
```

배열이므로 여러 건을 한 파일에 담을 수 있다.
`id`가 출력 폴더명이 되고, 파일은 `<id>_01.png` ~ `<id>_10.png`로 저장된다.

## 시리즈 설계

개별 캐러셀을 넘어 **전체 배열**을 기획한다.

### 필수 3종

| 카드 | 위치 | 역할 |
|---|---|---|
| **오프닝** | 첫 회차 | 시리즈 전체의 문제 설정 |
| **방법** | 중간 또는 끝 | 발굴 요령 전수 — **이것이 목적이다** |
| **게재 원칙** | 마지막 회차 | 하지 않은 것을 밝힘 |

**방법 카드가 가장 중요하다.**
발굴 성과를 자랑하고 끝내면 그것으로 끝이지만,
방법을 넘기면 다른 사람이 자기 주제로 같은 시도를 한다.

### 서사 배열 예시

```
1주  문제 제기    — 왜 안 보이는가
2주  방법의 증명  — 검색어를 바꾸니 나왔다
3~7주 발견        — 시대순 또는 주제별
8주  성찰         — 하지 않은 것 · 방법 전수
```

## 제작 후 점검

- [ ] 첫 장 제목이 피드 미리보기에서 읽히는가
- [ ] 게재 제한 대상의 화면이 섞이지 않았는가
- [ ] 10장 마지막에 「확인하지 못한 것」이 있는가
- [ ] 권리 배지와 근거 조문이 맞는가
- [ ] 재현 쿼리가 실제로 작동하는가
