# VLM 판독 프로토콜 — 신뢰도를 높이는 방법

OCR이 실패하는 자리를 시각언어모델(VLM)이 메운다.
다만 VLM은 **그럴듯하게 틀리는** 특성이 있으므로, 그대로 쓰면 OCR보다 위험하다.

## 왜 VLM인가

| | OCR | VLM |
|---|---|---|
| 손글씨 | 실패 | **부분 판독 가능** |
| 한자·세로쓰기 | 실패 | **부분 판독 가능** |
| 맥락 이해 | 없음 | **슬레이트 형식을 안다** |
| **환각** | **없음** | **있음 — 이것이 문제다** |

OCR은 못 읽으면 빈 결과를 낸다. **VLM은 못 읽어도 그럴듯한 답을 만든다.**
그러므로 VLM 판독에는 반드시 검증 절차가 붙어야 한다.

---

## 3단계 판독 프로토콜

```
① 폐쇄형 질문   무엇이 보이는지 형식을 지정해 묻는다
② 교차 검증     같은 대상을 다른 조건으로 다시 묻는다
③ 신뢰도 판정   일치도에 따라 등급을 매긴다
```

### ① 폐쇄형 질문

**나쁜 질문**: "이 이미지를 설명해 주세요"
→ 서술형 답변이 나오고, 없는 것을 지어낸다.

**좋은 질문**: 형식을 지정하고, 모르면 모른다고 답하게 한다.

```
이 촬영 슬레이트에서 다음 필드를 읽으십시오.
읽히지 않는 필드는 반드시 "판독불가"로 적으십시오.
추측하지 마십시오.

DATE:
UNIT:
SCENE:
ROLL:
CAMERAMAN:

각 필드마다 확신도를 [확실/부분/불가] 중 하나로 표시하십시오.
```

**「판독불가」를 명시적으로 허용하는 것이 핵심이다.**
그 선택지가 없으면 모델은 반드시 무언가를 적는다.

### ② 교차 검증 — 세 가지 방법

#### (가) 전처리 교차

같은 대상을 **다른 전처리 결과**로 각각 판독한 뒤 비교한다.

```bash
python scripts/analyze_image.py <이미지> --regions --out <디렉터리>
# region_01.jpg (원본 확대) · region_01_clahe.jpg (대비강화) 등을 각각 판독
```

전처리가 달라도 같은 답이 나오면 신뢰도가 올라간다.

#### (나) 부분 교차

전체를 한 번에 읽지 말고, **잘라낸 조각을 따로** 읽는다.

```
전체 슬레이트 판독:  "DATE 4/30/48"
DATE 필드만 잘라 판독: "4/30/48"
→ 일치. 신뢰도 높음
```

전체 판독에서만 나오고 조각 판독에서 안 나오면 **맥락에서 지어낸 것**이다.

#### (다) 형식 교차

판독 결과가 **그 형식의 규칙에 맞는지** 검사한다.

```bash
python scripts/analyze_image.py --identify "<판독한 문자열>"
```

- 날짜가 월/일/년 순으로 성립하는가
- 부대 표기가 알려진 패턴에 맞는가
- 지명이 당대 표기표에 있는가

**형식에 맞지 않으면 재판독한다.**

### ③ 신뢰도 등급

| 등급 | 조건 | 재기술 표기 |
|---|---|---|
| **확정** | 전처리·부분 교차 모두 일치 + 형식 합치 | 「~로 확정된다」 |
| **높음** | 두 가지 교차 일치 | 「~로 판독된다」 |
| **부분** | 일부 문자만 일치 | 「~로 보이나 일부 미판독」 |
| **불가** | 교차 불일치 또는 판독 실패 | **「판독하지 못하였다」** |

**「부분」 이하는 확정 사실로 쓰지 않는다.**

## 대상별 질문 틀

### 슬레이트

```
촬영 슬레이트입니다. 다음 필드만 읽으십시오.
읽히지 않으면 "판독불가"라고 적고, 추측하지 마십시오.

DATE / UNIT / SCENE / PROJECT / ROLL / CAMERAMAN / OFFICER / CAMERA

주의: 날짜는 미군 표기이므로 월/일/년 순입니다.
     보이는 그대로 적고, 해석은 하지 마십시오.
```

### 표지판·간판

```
이 표지판에 적힌 문자를 그대로 옮기십시오.
· 영문은 대소문자 그대로
· 한자는 정자로
· 한글은 그대로
· 읽히지 않는 글자는 □로 표시

의미 해석이나 번역은 하지 마십시오.
```

### 현수막·벽보

```
이 현수막의 문자를 옮기십시오.
줄 단위로 구분하고, 읽히지 않는 부분은 □로 표시하십시오.

⚠ 문맥으로 채워 넣지 마십시오.
   「信託統治決死□□」처럼 미판독을 남기는 편이
   틀린 글자를 채우는 것보다 낫습니다.
```

### 개체 식별

```
이 화면에서 다음만 답하십시오. 확실하지 않으면 "미확인"으로 적으십시오.

· 부대 마크가 보이는가 (예/아니오/불명확)
· 보인다면 형태는 (문자로만 기술, 부대 비정은 하지 말 것)
· 차량·항공기의 종류 (범주만: 트럭/지프/헬기/고정익 — 기종 특정 금지)
· 복장의 계절 (하계/동계/불명)
· 건축 양식 (기와/초가/근대식/불명)

⚠ 인물의 신원, 항공기 기종, 부대 번호는 추정하지 마십시오.
```

## VLM이 틀리는 전형적 방식

실무에서 반복적으로 관찰되는 오류 유형이다. 이것을 알면 검증 지점을 안다.

| 유형 | 증상 | 대응 |
|---|---|---|
| **맥락 보완** | 「信託統治決死反對」를 흐린 상태에서도 완성해 답함 | 조각 판독으로 교차 |
| **형식 완성** | 슬레이트 빈 필드를 그럴듯한 값으로 채움 | 「판독불가」 선택지 명시 |
| **연도 추정** | 화면 분위기로 「1950년대로 보입니다」 | 근거를 되묻는다 |
| **부대 비정** | 흐린 마크를 특정 사단으로 단정 | 형태 기술만 요구 |
| **인물 추정** | 유명인과 닮았다고 이름을 댐 | 인물 비정 금지 명시 |

> **VLM은 「모른다」고 말하기를 어려워한다.**
> 질문 설계에서 그 선택지를 강제로 열어 주어야 한다.

## 판독 기록 형식

VLM을 썼다면 **그 사실과 검증 방식을 반드시 기록한다.**

```markdown
| 시각 | 대상 | 판독 | 방법 | 신뢰도 |
|---|---|---|---|---|
| 0:12 | 슬레이트 DATE | 4/30/48 | VLM 3회 교차 일치 · 형식 합치 | **확정** |
| 0:12 | 슬레이트 UNIT | FE SIGNAL C CORPS | VLM 2회 일치 | 높음 |
| 3:05 | 벽보 | (판독 실패) | VLM·OCR 모두 불일치 | **불가** |
```

**「방법」 열이 있어야 다음 사람이 재검증할 수 있다.**

---

## 하지 말 것

- VLM 판독 결과를 **한 번만 묻고** 확정으로 쓰기
- 「~로 보입니다」라는 답변을 **「~이다」로 옮기기**
- 판독 실패를 **VLM에게 다시 물어 억지로 채우기**
- **인물·기종·부대 비정**을 VLM에게 맡기기

> 판독이 안 되면 **고해상도 사본 재판독을 후속 과제로 남긴다.**
> 이것이 추정해서 적는 것보다 언제나 낫다.
