# 아카이브 영상 분석 → 재기술 → 논문·전파 파이프라인

영상을 **프레임 단위로 분석해 정보를 추출하고**, 그 결과를 재기술·논문·전파물로 만든다.

이 파이프라인의 전제는 하나다. **원 기술은 대체로 부실하고, 때로는 틀렸다.**
표제 한 줄이 11분짜리 영상의 내용을 가리는 일이 흔하며, 날짜가 1년씩 어긋나 있기도 하다.
그러므로 **실물을 열어보지 않은 기술은 기술이 아니다.**

## 핵심 — 화면에서 정보를 뽑는다

영상 안에는 카탈로그가 담지 못한 정보가 있다.

| 대상 | 얻는 것 |
|---|---|
| **촬영 슬레이트** | **날짜·촬영자·부대·과제번호** — 가장 확실 |
| 표지판·간판 | 장소·시설명·부대 |
| 현수막·벽보 | 사건의 성격·구호 |
| 번호판·지상 표식 | 날짜·시설 번호 |
| 필름 리더 | 사본 세대·디지털화 이관 정보 |

실제로 이 방법으로 **촬영일 14건을 확정**하고 **카탈로그 오류 2건**을 발견한 사례가 있다.

---

## 발굴 스킬과의 관계

`korea-archive-discovery` 플러그인이 **자료를 찾으면**, 이 파이프라인이 **그것을 연다.**

| | 발굴 스킬 | 이 파이프라인 |
|---|---|---|
| 하는 일 | 자료를 찾는다 | 찾은 자료를 연다 |
| 끝나는 지점 | **식별자·URL 확보** | 논문 논거·전파물 |

```bash
# 발굴 결과를 판독 대기열로 — 우선순위까지 매긴다
python scripts/from_discovery.py <발굴결과> --out <디렉터리>
python scripts/from_discovery.py --paste "<MCP 응답>" --out <디렉터리>
```

**우선순위는 「원 기술이 무엇을 숨겼는가」로 매긴다.**
표제에 「ETC」가 있으면 +30, 「VARIOUS」면 +25, 권리 D등급이면 -40.

**왕복 구조를 잊지 말 것.** 판독에서 나온 단서(ROLL 번호·과제번호·촬영자·부대)로
다시 발굴 도구를 호출해 자매편과 계열 자료를 찾는다.
상세는 `references/discovery_handoff.md`.

## 전체 흐름

```
① 분석      ② 판독      ③ 재기술     ④ 판정      ⑤ 산출
프레임 추출  슬레이트    장면 목록    게재 4단계  논문 도판
문자 탐지    표지판      미확인 기록  권리 등급   캐러셀
전환 탐지    개체 식별   계열 관계               정합 검사
```

## ① 영상 분석

**순서가 중요하다.** 처음부터 확대 프레임을 뽑으면 어디를 확대할지 알 수 없다.

```bash
# 전 구간 개관 + 문자 후보 탐지 + 장면 전환 — 한 번에
python scripts/analyze_video.py auto <영상> --out <디렉터리>
```

개별 실행:

```bash
python scripts/analyze_video.py survey   <영상> --out <디렉터리>   # 전 구간 그리드
python scripts/analyze_video.py textscan <영상> --out <디렉터리>   # 문자 후보 상위 N개
python scripts/analyze_video.py scenes   <영상> --out <디렉터리>   # 장면 전환
```

### 문자 후보 탐지의 원리

슬레이트·표지판은 **고대비 + 규칙적 엣지**로 나타난다. 이를 점수화해 후보를 좁힌다.

| 점수 | 해석 |
|---|---|
| 18 이상 | 슬레이트 가능성 |
| 12~18 | 표지판·간판 가능성 |

**자동 탐지는 후보를 좁히는 도구이지 판정이 아니다.**
그리드를 눈으로 훑는 과정을 대체하지 않는다.

### 장면 전환이 중요한 이유

표제에 **「ETC」나 세미콜론**이 있으면 뒤에 무엇이 있는지 알 수 없다.
실제로 「ETC」 뒤에서 **대한민국 대통령의 극동사령부 방문**이 나온 사례가 있다.

## ② 판독

```bash
# 특정 시각을 여러 파라미터로 뽑아 가장 선명한 것을 자동 선택
python scripts/analyze_video.py zoom <영상> --at 125 --out <디렉터리>

# 영역을 좁히면 실질 해상도가 올라간다 (w,h,x,y — 0~1 비율)
python scripts/analyze_video.py zoom <영상> --at 125 --crop 0.45,0.75,0.35,0.05 --out <디렉터리>
```

필름 자료는 프레임마다 흔들림·초점이 달라 **한 장만으로는 판독이 안 된다.**
스크립트가 앞뒤 프레임 × 대비 3단계를 뽑아 최선을 고른다.

### 이미지 단독 분석 · OCR

프레임을 뽑았거나 사진 자료를 다룰 때는 이미지 분석기를 쓴다.

```bash
# 종합 — 문자 영역 탐지 + OCR 전수 시도 + 식별
python scripts/analyze_image.py <이미지> --out <디렉터리> --lang eng

# 문자 영역만 잘라내기 — 사람이 볼 판독용 조각
python scripts/analyze_image.py <이미지> --regions --out <디렉터리>

# 판독한 텍스트를 구조화 — 슬레이트 필드·날짜·지명·부대
python scripts/analyze_image.py --identify "DATE 4/30/48 UNIT FE SIGNAL C CORPS SCENE FEC 67 CHEJU"
```

**`--identify`가 실질적으로 가장 유용하다.** 판독한 문자열을 넣으면:

| 입력 | 출력 |
|---|---|
| `4/30/48` | **1948년 4월 30일** (미군 자료는 월/일/년 순) |
| `CHEJU` | **제주** |
| `SAISHU` | **제주 (일본식 독음)** |
| `FE SIGNAL C CORPS` | **극동 통신대** |
| `; ETC` | **⚠ 표제가 가린 내용이 있을 수 있다** |

### ⚠ OCR의 한계를 먼저 안다

사료 프레임은 저해상도·필름 그레인·흔들림이 겹쳐 **일반 OCR 정확도가 매우 낮다.**

| 대상 | 성공 여부 |
|---|---|
| 인쇄체 영문 대문자 | 부분 성공 |
| 큰 글씨 고대비 문자 | 부분 성공 |
| **손글씨** (슬레이트 기입 대부분) | **사실상 실패** |
| **한자·세로쓰기 간판** | **사실상 실패** |

**그러므로 OCR은 판독을 대신하지 않는다.**
스크립트의 실질적 가치는 **문자 영역을 찾아 잘라 주는 것**에 있다.
잘린 조각(`region_*.jpg`)을 직접 보고 판독하라.

**OCR 결과를 그대로 재기술에 옮기면 안 된다.**

### VLM으로 신뢰도를 높인다

OCR이 실패하는 자리를 시각언어모델이 메운다. **다만 VLM은 그럴듯하게 틀린다.**

| | OCR | VLM |
|---|---|---|
| 손글씨·한자 | 실패 | 부분 판독 가능 |
| **환각** | **없음** | **있음 — 이것이 문제** |

OCR은 못 읽으면 빈 결과를 내지만, **VLM은 못 읽어도 답을 만든다.**
그러므로 3단계 프로토콜을 따른다. 상세는 `references/vlm_reading.md`.

```
① 폐쇄형 질문   형식을 지정하고 「판독불가」를 명시적으로 허용
② 교차 검증     전처리 교차 · 부분 교차 · 형식 교차
③ 신뢰도 판정   확정 / 높음 / 부분 / 불가
```

**「판독불가」 선택지를 열어 주지 않으면 모델은 반드시 무언가를 적는다.**

판독 방법과 개체 분석의 한계는 `references/frame_analysis.md`를 읽는다.

**판독에 실패하면 실패를 기록한다.** 추정해서 옮겨 적지 않는다.

## ③ 재기술

`references/redescription.md`를 읽고 수행한다.

**필수 항목 다섯**: 한국어 제목 · 시각별 장면 목록 · 확인된 것 · **확인하지 못한 것** · 검색어

**「확인하지 못한 것」이 핵심이다.** 발굴 성과만 적으면 그것은 홍보이지 기술이 아니다.

## ④ 게재 판정

`references/publication_ethics.md`를 반드시 읽는다.

퍼블릭 도메인이라고 다 실을 수 있는 것이 아니다. **기준은 권리가 아니라 피촬영자의 처지다.**

| 단계 | 기준 | 조치 |
|---|---|---|
| 1 | 개인 미특정 | 자유 게재 |
| 2 | 공개 활동 중 얼굴 | 개인 중심 프레임만 제외 |
| 3 | 개인 식별 촬영 포함 | **비식별 장면만** |
| **4** | **거부할 수 없었던 처지** | **화면 일절 미사용 · 추출 프레임도 삭제** |

권리 등급도 함께: **B**(17 U.S.C. §105) · **C**(허가 필요) · **D**(36 CFR 1254.62 — 공개 금지)

## ⑤ 산출

### 논문용

```bash
python scripts/make_figure.py panel <사양.json> --out fig.png   # 도판 패널
python scripts/make_figure.py stats <데이터.json> --out fig.png  # 통계 도표
python scripts/make_figure.py cite  <메타.json>                  # 인용 형식
```

논거 유형과 한계 절 작성법은 `references/academic_output.md` 참조.

**도판은 예쁜 사진이 아니라 논거다.** 캡션에 **무엇을 판정하지 않았는지**를 반드시 적는다.

### 메타데이터·온톨로지

재기술 결과를 기계가 읽을 수 있게 만든다. 이것이 있어야 **여러 건을 이어 붙일 수 있다.**

```bash
python scripts/make_metadata.py check <판독.json>              # 필수 항목 검사
python scripts/make_metadata.py build <판독.json> --out <디렉터리>  # 전부 변환
```

산출:

| 파일 | 표준 | 용도 |
|---|---|---|
| `metadata.jsonld` | **RiC-O + CIDOC-CRM** | 기록 기술 + 사건 모형 |
| `karda_nodes.csv` · `karda_edges.csv` | — | **KARDA 관계 발견 입력** |

**신뢰도 필터가 걸려 있다.** 「높음」 이상만 확정 속성으로 나가고,
「부분」 이하는 `kad:tentative*`로만 표기되어 그래프에 실리지 않는다.
**한번 그래프에 들어간 오류는 관계 추론을 통해 증폭되기 때문이다.**

로컬 확장 `kad:unconfirmed`로 **확인하지 못한 것도 기계 판독 가능하게** 남긴다.

관계 유형과 질의 예는 `references/ontology.md` 참조.

### 전파용

```bash
python scripts/make_carousel.py <사양.json>
```

서사 구조 10장. 설계는 `references/carousel_design.md`, 캡션 작성은 `references/promotion.md`.

### 정합 검사

```bash
python scripts/check_consistency.py <디렉터리> --promo 홍보글.md \
  --sources 재기술.md --logs 일지.md --restricted <제한 식별자들>
```

산출물이 늘어나면 수치가 문서마다 갈린다. 대외 발신물의 사실 근거도 검사한다.

**검사를 만들 때 절반의 노력은 「무엇을 잡지 않을지」에 든다.**
작업 일지의 과거 수치, 금지 표현 목록 자체, base64 안의 우연한 문자열 —
오탐이 잡히면 검사 자체가 무시된다.

## 작업 원칙 다섯

1. **확인한 것만 쓴다** — 추정은 「추정」이라 적는다
2. **못 한 것을 적는다** — 미확인 목록이 없으면 완결이 아니다
3. **자기 오류를 밝힌다** — 정정 이력을 남긴다
4. **할 수 있어도 하지 않는다** — 권리와 게재는 다른 문제다
5. **수치는 재현 가능하게** — 쿼리와 조회 시점을 명기한다
