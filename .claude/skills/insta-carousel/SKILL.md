# 인스타 캐러셀 카드뉴스 제작

콘텐츠를 받아 **1080×1080 PNG 카드 6~10장 + 게시 캡션**을 산출한다.
파이프라인: ①재료 파악 → ②발굴조사(주제가 실존 대상일 때) → ③이미지 소싱 → ④서사 설계
→ ⑤HTML 카드 작성 → ⑥`scripts/make_carousel.py` 렌더링 → ⑦**PNG 육안 검수(생략 금지)**
→ ⑧캡션·해시태그.

## 0. 재료 파악

시작 전에 확인한다. 대화에 이미 답이 있으면 묻지 말 것.
- **주제·목적·CTA**: 무엇을 홍보하나? 독자가 마지막 카드에서 할 행동은?
- **장수**: 사용자가 개수를 지정했으면("7장으로", "카드 5개") **정확히 그 수**로 서사 아크를
  병합·확장해 설계한다 — 임의로 늘리거나 줄이지 않는다. 렌더 시 `--expect N`으로 검증.
  지정이 없으면 기본 8~10장(인스타 최대 10), 내용이 적으면 6장.
- **이미지**: **실물 이미지가 캐러셀의 신뢰를 만든다** — "텍스트만 많으면 신뢰가 안 간다"는
  사용자 피드백이 이 스킬의 출발점이다. 사용자가 준 사진이 없어도 주제가 실존 대상(기관·유물·
  사건·인물)이라면 퍼블릭 도메인/공공누리 실물 이미지를 능동적으로 발굴하라.
  소싱 방법·라이선스 판정은 `references/image-sourcing.md`를 읽는다.
- **권리·출처**: 이미지가 들어간 모든 카드에 출처 캡션 필수 — 표준 형식은
  `출처: [기관 정식명칭], [식별번호] ([라이선스])`. 식별번호(NAID·원판번호·소장번호·파일명)를
  아는데 생략하는 것은 부정확한 출처다. 소싱하는 즉시 이미지별 **출처 대장(`sources.txt`)**을
  기록하고 납품물에 포함한다(형식은 `references/image-sourcing.md`). 기관은 정식 명칭
  (사이트 title로 확인), 라이선스 미확정이면 "게시 전 [권리자] 확인" 안내 동봉.

## 0.5 발굴조사 — 재료가 없으면 캐러 간다

주제가 실존 대상(기관·유물·사건·인물·기록물)인데 사용자가 재료를 주지 않았다면,
**만들기 전에 조사한다.** 조사의 깊이가 콘텐츠의 차별성이다 — 남들이 아는 사실 나열이
아니라 직접 발굴한 기록·디테일·반전이 카드가 된다. 방법론은 `references/discovery.md`를
읽는다. 요지:
- **넓게→좁게** + **표기 변형 병렬 투입**(당대 표기·로마자 변형이 검색의 반이다) + 복수 아카이브 교차검색
- **인접 채굴**: 식별번호 하나를 찾으면 이웃 번호(±5~15)를 훑는다 — 최고 수익률 기법
- **0건 ≠ 부재**: 공개 상태를 🟢완전공개/🟡카탈로그만/🔴미공개 3단계로 실검색 판정
- **제목을 의심**: 생산일자·원판번호까지 확인 — 검증에서 나온 반전이 최고의 카드가 된다
- 실행한 쿼리·건수·확인일을 기록 — "따라하기" 카드와 캡션의 재현 검색이 된다

## 1. 서사 설계

카드는 나열이 아니라 서사다. 기본 아크(장수에 맞게 병합):

| # | 역할 | 비고 |
|---|---|---|
| 1 | 커버 후킹 | 실물 이미지 풀블리드 + 숫자·시간 대비 또는 통념 뒤집기 훅 |
| 2 | 디테일/원리 | 가장 흥미로운 세부 하나 확대 (손글씨·연호·이상치) |
| 3~6 | 증거 | 실물 이미지 카드들 — 스킬의 심장 |
| 7 | 정리 | 표·지도·타임라인·3단계 분류 등 구조화 카드 |
| 8 | 전량 공개/검증 | 콘택트시트, 또는 "제목만 믿으면 틀린다"류 검증 노트 |
| 9 | 따라하기 | 독자가 재현 가능한 단계 — 재현성이 신뢰 장치다 |
| 10 | CTA | 행동 1개 + 댓글 유도 + 출처·권리 고지 |

**검증 노트 카드**는 이 스킬의 차별점이다: 조사 중 발견한 반전(오표기 기록, 메타데이터 디테일,
연호, 인접 발굴)을 한 장으로 만들면 콘텐츠의 백미이자 계정의 신뢰 장치가 된다.
카피 공식·캡션 스타일은 `references/copywriting.md` 참조.

## 2. 사실 검증 — 콘텐츠의 생명

역사·조사 콘텐츠는 틀리면 끝이다. 카드에 넣기 전에:
- **제목만 믿지 않는다** — 생산일자·원판번호까지 확인한다. (실례: '해방 기념식'이라는 제목의
  영상이 메타데이터 확인 결과 1950년 수복 기념식이었다 — 이 검증 과정 자체가 좋은 카드가 됐다)
- **실증 안 된 어록 금지** — 출처 있는 어록만. 전승 어록은 "전해지는 말" 표기, 인용부호 없이
  편집 문장으로 대체하는 것도 방법. 어록 사용 시 카드나 캡션에 관련 고지 한 줄.
- **검증 불가한 비교 대신 산술** — "○○시보다 많다"(검증 부담) 대신 "매일 100가구꼴"(계산 가능).
- 민감 주제(학살·포로·희생자)는 존엄 문구를 캡션에 포함하고 이미지 선택을 보수적으로.

## 3. HTML 카드 작성

`assets/card_styles.html`을 읽고 시작한다 — 검증된 고대비 디자인 시스템(순흑 배경 + 크림 +
크림슨/골드, 필름 그레인, 골드 프레임)과 컴포넌트 전부가 들어 있다. 주제에 맞게 :root 팔레트만
바꿔도 된다. 레이아웃 아키타입(파노라마·부채꼴 스택·지도 여정·인물 카드·빅넘버·타임라인 등)의
선택 기준은 `references/layouts.md`를 읽는다 — **같은 레이아웃 반복은 지루하다. 한 캐러셀에
서로 다른 아키타입을 3개 이상 섞어라.**

구조 규칙:
- 카드 = `<div class="card">` (1080×1080, overflow:hidden)
- **모든 카드의 콘텐츠는 `<div class="col">` 안에** — 이 클래스가 하단 안전영역
  (padding-bottom 150px)을 확보해 페이지번호·브랜드와의 겹침을 구조적으로 막는다.
  이것이 이 작업의 1번 반복 결함이었다: **credit에 `margin-top:auto`를 쓰지 말 것**
  (내용이 짧은 카드에서 하단 표기와 충돌한다). 고정 마진(예: margin-top:20px)을 쓴다.
- 이미지는 `{{img:경로|maxdim=760|q=72}}` 토큰 — 렌더 스크립트가 리사이즈·base64 임베드 처리
- **이미지에 고정 높이 + `object-fit:cover`** 필수 — 미지정 시 세로가 밀려 카드가 넘친다
- 겹침 레이아웃(부채꼴 스택·테이프)은 **제목 영역을 침범하지 않게** 아래쪽에 배치
- 이미지 카드마다 출처 한 줄(.credit)

세로 예산: 상하 패딩+안전영역 220 + 키커 60 + 제목 150 → 콘텐츠 가용 **~650px**.
이미지 높이 합+캡션+리드가 이걸 넘으면 잘린다. 설계 때 합산하고, 최종 판정은 렌더 후 눈으로.

## 4. 렌더링 — 번들 스크립트

```bash
python scripts/make_carousel.py template.html --outdir out --expect 8     # 전체 (장수 검증)
python scripts/make_carousel.py template.html --outdir out --only 3,7     # 수정분만 재렌더
```
토큰 임베드 → 카드 분리 → 헤드리스 크롬/엣지 캡처 → 크기 검증까지 한 명령.
`--expect N`은 카드 수가 N과 다르면 오류로 중단한다 — 사용자가 장수를 지정한 작업에서는
반드시 붙여서 약속한 개수를 기계적으로 보증하라. `--size 1080x1350`(세로형) 지원.
의존성: Python+Pillow, Chrome/Edge.

## 5. 육안 검수 — 생략 금지

**PNG 전부를 Read 도구로 열어 확인한다.** 경험상 첫 렌더에서 2~4장은 결함이 있다.
1. **하단 겹침·세로 넘침** (최다 결함) — 출처 줄이 브랜드/페이지번호를 침범하는지
2. **이미지 적합성** — 빈 컷·뒷면·무관한 컷·워터마크본·현대 2차창작이 섞이지 않았는지.
   단, 뒷면 메모·손글씨 같은 디테일은 버리지 말고 스토리로 살릴 것
3. 어색한 줄바꿈(한 단어 고아), 텍스트 대비, 페이지 번호 순서
결함 카드만 고쳐 `--only`로 재렌더한다. 검수 없이 납품하지 않는다.

## 6. 캡션 — 짧고 굵게

`caption.txt` 구성: 본문 캡션 / 릴스·스토리용 짧은 버전 / 해시태그(본문 ~20 + 첫 댓글 확장)
/ 게시 전 체크리스트. **본문 캡션은 한 줄 한 호흡** — 긴 문단 금지, 질문형 오프닝
("이 필름, 본 적 있으세요?"), 한두 문장마다 빈 줄, 이모지 불릿으로 구조화. 스크롤 중
멈춰 읽게 만드는 시각적 리듬이 목적이다. 상세 공식은 `references/copywriting.md`.

## 7. 시리즈 연재물일 때

- 예고편 캐러셀: 커버(대표 이미지 스트립) + 부작별 티저(대표 이미지+공개일 배지) + 일정표 CTA
- 브랜드 표기·팔레트·프레임을 전 편 동일하게 — 피드에서 시리즈로 인식되게 한다
- 공개일 요일은 실제 달력으로 검산하고, 날짜 변경 시 `--only`로 해당 카드만 재렌더

## 8. 납품

- 순서대로 번호 붙은 PNG 전체 + `caption.txt` + `sources.txt`(이미지별 출처 대장)
  + 자기완결 `carousel.html`(수정용 원본)
- 사용자가 장수를 지정했으면 납품 PNG 개수가 일치하는지 최종 확인
- 파일 전송 도구가 있으면 PNG를 render로 표시
- 라이선스 미확정 이미지가 있으면 "게시 전 [권리자] 확인" 안내 필수
