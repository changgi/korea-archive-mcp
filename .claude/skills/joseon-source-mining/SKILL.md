# 조선 사료 심층 판독 스킬

## 이 스킬이 다루는 것

`korea-archive-discovery`가 **자료를 찾는** 스킬이라면, 이 스킬은 **찾은 자료를 읽고
제도를 재구성하는** 스킬이다. 검색 결과 목록에서 멈추지 않고 조문·기사 본문까지 열어
"이 제도가 언제 생겨서 어떻게 작동하다 어떻게 끝났는가"를 복원한다.

한강 강배 기록 발굴 조사(2026-08-18, 1485~1986)에서 검증되었다. 그 조사는
비변사등록 실질 기사 109건 전건 본문 확보, 규장각 원전 6종 원문 이미지 수집,
법전 조문 30여 건 판독으로 **법전에 없는 제도(執籌 배정 체계)가 150년간 작동하다
법전 개정 없이 소멸한 과정**을 재구성했다.

## 1. 접근 경로 — 전부 POST다

**가장 흔한 실패는 GET으로 시도하는 것이다.** 한국사DB 계열은 검색이 전부 POST이며
GET은 404 또는 400을 낸다. 아래는 실측 확인된 파라미터다.

### 한국사DB (db.history.go.kr)

```
[통합 검색]  POST /search/searchTotalResult.do
             totalWord=<검색어>&chinessChar=on&synonym=off
             ※ 한자 검색 시 chinessChar=on 필수

[법령 검색]  POST /search/law/searchResultList.do
             searchItemId=jlaw&searchTarget=jlaw&totalWord=<검색어>
             &pageUnit=50&pageIndex=1&orderColumn=levelId&orderDir=ASC
             &chinessChar=on&synonym=off

[비변사등록] POST /joseon/search/searchResultList.do
             searchItemId=bb&searchTarget=bb&totalWord=<검색어>
             (그 밖 파라미터는 법령과 동일)

[상세 조회]  법령    GET /joseon/item/level.do?levelId=<levelId>
             등록류  GET /joseon/level.do?levelId=<levelId>
             ※ 경로가 다르다. item/ 유무를 혼동하면 빈 페이지가 온다

[인용 URL]   https://db.history.go.kr/id/<levelId>
```

### 승정원일기 · 실록

```
[승정원일기] POST https://sjw.history.go.kr/search/searchResultList.do
             searchTerm=<검색어>&topSearchWord=<검색어>&pageUnit=50&pageIndex=1

[실록]       POST https://sillok.history.go.kr/search/searchResultList.do
             topSearchWord=<검색어>&topSearchWord_ime=<검색어>
```

### 규장각 (kyudb.snu.ac.kr) — web_fetch 차단, 직접 요청은 가능

```
[검색]       POST /search/search.do
             totalSearchString=<검색어>&searchArea=10   ← 목록
             totalSearchString=<검색어>&searchArea=20   ← 해제(解題)

  ★ 절목·사목류는 상위 서명 아래 편차(編次)로 들어가 있어
    목록 검색으로는 안 나온다. 반드시 searchArea=20(해제)도 조회할 것.

[원문 이미지] fn_originalImg(item_cd, book_cd) 확인 →
             POST /pf01/rendererImg.do →
             GET /ImageServlet.do?imgFileNm=..&path=/data01/stream/{item_cd}/IMG/{book_cd}/{book_cd}_0001/..
```

**item_cd는 자료 성격별로 다르다.** 실측 확인된 5종:

| item_cd | 자료 유형 | 예 | 파일명 패턴 |
|---|---|---|---|
| ART | 도설·회화 | 各船圖本 奎15752 | `GK15752_00_IL_0001_000a.jpg` |
| ETC | 두루마리·축 | [戰兵]各船圖本 奎軸12163 | `GK12163_00_IH_0001_0001.jpg` |
| DRR | 등록류 | 禁營津船謄錄 奎19356 | `GK19356_00_IH_0001_000a.jpg` |
| FND | 재정·사목 | 均役廳事目 奎17252 | `GK17252_00_IL_0001_000a.jpg` |
| POL | 정책·절목 | 舟橋指南 奎5485 | `GK05485_00IH_0001_0001.jpg` ← **밑줄 없음** |

**주의** — 舟橋指南(POL)만 파일명 규칙이 다르다(`00IH`, 4자리 일련번호).
새 자료를 열 때는 **첫 이미지 URL을 실제로 받아 보고 패턴을 확정**한 뒤 순회할 것.

`references/access_recipes.md`에 실행 가능한 코드가 있다.

## 2. 판독 전략 — 여섯 가지

### ① 형제 조(兄弟 條)를 반드시 전수 확인한다 【최우선】

**편(編)·조(條) 구조를 가진 사료에서 총론만 읽고 끝내면 핵심을 놓친다.**

한강 조사에서 이 실수를 **두 번** 했다. 『萬機要覽』 舟橋 편과 『六典條例』 舟橋司 편을
같은 날 조회하면서 **둘 다 총론만 열었다.** 뒤늦게 형제 조를 열자 이것들이 나왔다.

- 『萬機要覽』 舟橋 [舟橋船] — **배다리 전체 자재 명세**(縱樑 175주·鋪板 1,039립·牽馬鐵 5,804개)
- 『萬機要覽』 舟橋 [津路] — **능침별 도강 지점 지정**(단 한 줄이 조사의 미해결 질문을 해소)
- 『萬機要覽』 舟橋 [員額] — 인원 편성(旗軍 456÷격군 12 = **38척**, 자재 명세와 교차 검증)
- 『六典條例』 舟橋司 [卷首] 舟橋 — **시공 시방 전문**
- 『六典條例』 舟橋司 [卷首] 漕運 — **배정 산식**(배 3등 × 읍 3등)

**전부 첫날 열었던 그 편(編) 안에 있었다.**

```
실행 방법: levelId의 마지막 4자리를 0010, 0020, 0030… 으로 순회한다.
          예 jlawb_400_0050_0090_0030 → _0010 _0020 _0040 도 조회
          응답이 "조선시대법령자료 메뉴"만 담고 있으면 그 번호는 없는 것이다.
```

**그리고 그 확인은 검색 결과를 받은 그 자리에서 한다.** 미루면
"이미 답을 얻었다"고 착각한 채 다음 단계로 넘어간다.

### ② 국역의 註(주석)를 독립된 정보원으로 읽는다

한강 조사에서 **국편 국역의 주석이 결정적이었던 것이 세 번**이다.

- **경강(京江)의 범위** — 註가 '뚝섬~양화도'로 정의
- **執籌船의 정체** — "주교사 장부에 등록된 京江 大船 … 담당 지역을 **추첨**해서 배정받았기
  때문에 執籌船이라고도 함" → 배 이름의 어원과 독점 구조가 한꺼번에 풀림
- **八江의 구성과 출전** — "纛島·西氷庫·新村里·龍山·麻浦·土亭·西江·望遠亭 … 『六典條例』
  「工典 舟橋司 總例」" → **출전이 이미 판독한 조문**이었음을 알려줌

**번역문의 주석은 부속물이 아니다.** 원문만 보면 놓치는 정보가 들어 있고,
특히 **용어 정의와 출전 지시**가 많다.

### ③ 검색 건수를 그대로 믿지 않는다 — 좌목(座目)을 걸러라

비변사등록에서 「舟橋司」 검색 결과가 **601건**이었다. 그런데 그중 **492건이 座目**
(회의 참석 관원 명단)이었다. **실질 기사는 109건**이다.

```
필터: 표제가 '…좌목'으로 끝나면 제외
      re.search(r'좌목$', title.strip())
```

**검색 건수를 분포 지표로 쓰기 전에 반드시 표제 유형을 분류할 것.**
"1,882건이 나왔으니 중요한 주제"라는 판단이 통째로 틀어질 수 있다.

### ④ 법전 수록 여부를 대조해 '부재'를 발견한다

어떤 제도가 **법전에 있는지 없는지**를 확인하는 것 자체가 발견이다.

한강 조사에서 강배 어휘 14종의 법령 건수를 나란히 놓았다.

```
船價 182 · 津夫 105(經國大典부터) · 漕倉 79 · 水站 76 · 渡丞 75(經國大典)
· 船格 68 · 站船 48 · 沙格 42 · 舟橋司 30 · 賃船 28 · 都沙工 19
· 舟橋船 6 · 執籌船 1  ← 그마저 법전이 아니라 『度支志』 「事實」(사례 편목)
```

**결론** — 조선은 배·사람·나루·삯·창고를 법전으로 규율했으나
**"어느 배에 어느 노선을 줄 것인가"만은 법전 밖에 두었다.**
가장 이해가 첨예한 배분 문제가 성문화되지 않은 채 150년을 갔다.

**제도사를 법전으로만 재구성하면 이런 제도는 존재하지 않는다.**
등록류·일기류를 함께 읽어야 보인다.

### ⑤ 핵심 어휘의 연원을 다른 법 영역에서 추적한다

제도 용어가 **원래 무엇을 가리키던 말인지**를 확인하면 제도의 성격이 드러난다.

- **執籌** → 원래 **노비 상속 분할** 용어. 『受敎輯錄』(1543) "부모가 나누지 않은 노비를
  자녀들이 **和會執籌 分衿**(모여 산가지를 잡아 몫을 나눔)"
- **抽籤** → 원래 **강경(講經) 시험** 용어. 『經國大典』 禮典 "성균관은 **매일 抽籤**하여
  諸生이 읽은 책을 강한다"

둘 다 "여럿 사이에 공정하게 배분하는 절차"를 가리키는 일반 용어였고,
18세기에 조운으로 옮겨 왔다. **징발의 대가를 상속 분할의 언어로 표현한 것이다.**

### ⑥ 목차가 범위를 좁힌다

『均役廳事目』 81장에서 선박세 조문을 찾을 때, **목차 한 줄**이 결정적이었다.

```
005a 목차: "分爲十條 曰設廳 曰結米 曰結餘 曰海稅 曰軍官 曰移設
            曰減革 曰給代 曰需用 曰會錄"
→ 선박세는 「海稅」 조 → 80장이 17장 부근으로 좁혀짐 → 017a에서 발견
```

**원문 이미지를 순회하기 전에 목차·범례 지면을 먼저 열 것.**

## 3. 제도 재구성 — 다섯 축 프레임

조선의 행정 제도를 읽을 때 아래 다섯 축으로 정리하면 누락이 줄어든다.
한강 조사에서 선박 행정을 이렇게 복원했다.

| 축 | 묻는 것 | 한강 사례 |
|---|---|---|
| **등록** | 대상을 어떻게 파악했나 | 每年推刷·尺量·刻字號烙印·船主成案 |
| **측정** | 무엇으로 쟀나 | 營造尺 → **量船尺**(1750년 신설, 단위 把) |
| **운항·규율** | 어떻게 통제했나 | 行狀·計程定限·연대책임(船主+管領+切隣) |
| **동원** | 어떻게 가져갔나 | 分等抽籤·체대자 징발 |
| **보상** | 무엇으로 갚았나 | 세곡 운송권 배정(형식은 恩典) |

**그리고 반드시 마지막을 확인한다** — 그 제도가 **언제 어떻게 끝났는가.**
한강 조사에서는 1882년 執籌船 영구 혁파와 1887년 "이미 혁파한 것을 곧바로
다시 설치할 수 없다"가 서사를 닫았다.

**끝을 찾지 못하면 제도사가 아니라 제도 소개에 그친다.**

## 4. 검증과 인용 — 두 층위로 나눠라

**한문 인용의 안전 등급이 사료 유형마다 다르다.** 이것을 뭉뚱그리면
원문을 직접 옮긴 부분까지 불필요하게 평가절하된다.

| 등급 | 대상 | 인용 가능성 |
|---|---|---|
| **ⓐ 원문 직접** | 법전·편람(경국대전~육전조례·만기요람) — 조선시대법령자료에 **한문 원문 제공** | 인용 가능. 단 **표점은 DB 형태**이며 교감본 미대조임을 밝힐 것 |
| **ⓑ 역구성** | 등록·일기(비변사등록·승정원일기) — **국역만 노출** | **학술 인용 불가.** 한문 표기는 국역에서 역으로 구성한 것 |

**단, 한자 색인은 존재한다.** 비변사등록에서 `添載`로 검색하면 961건이 나온다.
즉 **원문 텍스트는 DB에 있으나 화면에 국역만 노출되는 구조**다.
원문 열람 경로는 국사편찬위원회에 문의하면 해결될 수 있다.

**그 밖에 반드시 밝힐 것**
- 초서 판독 미실시 여부
- 척 환산 시 실측 계열 차이(영조척은 세종대 31.22cm / 유물 평균 30.46cm /
  황종척 환산 30.65cm — 최대 2% 차이)
- 범위 개념의 기준 상충(예: 경강 = 광나루~양화진 / 뚝섬~양화도 / 三江 / 八江)

## 5. 링크 유효성 검증 — 마무리 필수

보고서를 닫기 전에 **인용한 levelId와 URL을 전수 조회**한다.
`references/link_check.py`를 쓰거나 같은 방식으로 재현한다.

**두 가지를 나눠 본다.**
1. **HTTP 200** — 링크가 살아 있는가
2. **본문 존재** — 내용이 실제로 있는가 (마커: `◯`/`○` 또는 상세 영역)

**이 둘은 별개다.** 한강 조사에서 1건이 **200 응답에 본문 없음**으로 나왔는데,
확인해 보니 **항목은 존재하고 URL도 유효한데 본문이 공개되지 않은 것**이었다.
"본문 추출 실패"가 아니라 **자료의 공개 범위** 문제였다.

**'도달하지 못했다'와 '공개되지 않았다'는 다르고, 후자는 재시도로 해결되지 않는다.**

**이상으로 나온 링크는 원인까지 규명한다.** 한강 조사에서 외부 URL 71개 중
11건이 이상이었으나 **사망 링크는 0건**이었다.

| 증상 | 실제 원인 |
|---|---|
| 조회 실패 | HTML의 `&amp;`를 그대로 조회 — 해제하면 정상 |
| 202 응답 | 봇 차단이 아니라 **비동기 응답**(TNA) |
| 타임아웃 | 기관 서버가 느린 것(:8443 포트 등) |
| 400 응답 | **POST 기반 검색 URL**은 GET으로 재현 불가 |

**실패를 기록하는 것만으로 부족하다. 원인까지 규명해야 다음 사람이 헛수고하지 않는다.**

---

## 6. 산출물 정합 — 도구로 점검한다

긴 조사를 여러 회차에 걸쳐 키우면 **새 발견은 뒤에서 늘어나는데 앞 지면과
부속 산출물은 그대로 남는다.** 한강 조사에서 이 정합이 **여덟 번** 깨졌고,
원인은 매번 같았다 — **"확인했다"고 적었으나 실제로 대조하지 않았다.**

**절차를 만들고 확인 방법까지 적어도 반복된다. 사람의 주의력에 의존하면 실패한다.**

`references/consistency_check.py`를 쓴다. 세 가지를 한다.

1. **산출물 × 핵심 어휘 수록 매트릭스**
2. **본문 내부 구역별 매트릭스**(요약·정책·전시·해설·체크리스트 등)
3. **수치 표기 대조**(정정 횟수·노드 수·장수 등이 파일마다 어긋나는지)

**설계 원칙** — 판단하지 않는다. 있는지 없는지만 본다.
출력의 '미수록'은 **오류 목록이 아니라 판단 목록**이다.
한강 조사에서 도구가 낸 104건 중 **실제 오류는 3건**이었고, 나머지는
산출물 성격상 정상이었다. **도구는 후보를 내고, 사람은 산출물의 성격을 안다.**

그 3건 중 하나가 **중심 사료의 전거 누락**(보고서의 핵심 명제를 지탱하는
1767년 형량표가 전거대장에 없었다)이었다는 점에서 도구는 제 값을 했다.

---

## 7. 자기 정정을 기록한다

한강 조사는 **네 차례 자기 정정**을 거쳤고 그 이력을 본문에 남겼다.

1. 2차 자료에 의존해 도판 순서를 잘못 적음
2. 검색 601건을 분포 지표로 씀 — 492건이 좌목이었음
3. **조문 존속을 제도 존속으로 읽음** ("370년 불변"은 조문 이야기였다)
4. **편·조 구조 사료에서 형제 조를 확인하지 않음** — 두 사료에서 반복

**재현 가능성을 담보하는 것은 실패 목록이 아니라 정정 이력이다.**
못 찾은 것은 대개 나중에 열린다. 그러나 **틀린 판단은 기록하지 않으면 사라진다.**

산출물의 마무리 메시지도 그래서 바꿨다 —
"찾지 못한 것도 적는다" → **"틀린 것도 적는다."**

## 8. MCP 도구가 있으면 (korea-archive 서버)

★ 정식 korea-archive 서버(korea-archive-mcp.vercel.app)에서는 아래 기능이 **`nedb_search`의 mode 파라미터**로
통합 노출된다(PlayMCP 20도구 상한): law=joseon_law_search · record=joseon_record_search(座目 필터) ·
item=joseon_item_read · sibling=joseon_sibling_scan · matrix=law_presence_matrix · origin=term_origin_trace ·
sjw=sjw_search · kyujanggak=kyujanggak_search(+이미지 패턴 지식). 아래 이름은 단독 실행(joseon_tools.py CLI)용.

```
joseon_law_search      법전·편람 조문 검색(조선시대법령자료)
joseon_record_search   등록류 검색(비변사등록 등) + 좌목 자동 필터
joseon_item_read       levelId로 본문 조회(법령/등록 경로 자동 판별)
joseon_sibling_scan    ★ 형제 조 전수 스캔(총론만 읽는 실수 방지)
kyujanggak_search      규장각 검색(목록 + 해제 동시)
kyujanggak_images      원문 이미지 수집(item_cd 자동 탐지)
sjw_search             승정원일기 검색
term_origin_trace      어휘 연원 추적(다른 법 영역 용례 대조)
law_presence_matrix    법전 수록 여부 대조표(부재의 발견)
link_verify            levelId·URL 전수 검증(200 + 본문 존재 분리)
consistency_audit      산출물 정합 점검
```

없으면 위 1~7절 규칙대로 직접 요청·조회로 수행한다.
`references/mcp_tool_spec.md`에 각 도구의 입출력 스키마가 있다.

## 9. 산출 형식

조사가 끝나면 **HTML 보고서**를 생성한다.
`korea-archive-discovery`의 `report_template.html`을 쓰되, 조선 사료 조사에는
아래 절을 추가한다.

- **제도 재구성 절** — 다섯 축(등록·측정·운항·동원·보상) + 제도의 끝
- **법전 수록 대조표** — 부재를 데이터로 표시
- **어휘 연원** — 핵심 용어가 어디서 왔는가
- **검증 한계** — 인용 등급 2층위(ⓐ원문 직접 / ⓑ역구성), 초서·표점·환산 미실시 여부
- **링크 검증 결과** — 200/본문 분리, 이상 건의 원인 규명
- **자기 정정 이력** — 지우지 말 것

전거는 반드시 **levelId · 인용 URL · 원문 제공 여부**를 함께 적는다.
원문 제공 여부가 없으면 다음 사람이 인용 가능성을 판단할 수 없다.

## 10. 이 스킬을 쓸 때의 기본자세

- **0건은 부재가 아니다.** 접근 방식을 바꾸면 열린다(한강 조사에서 '못 찾음' 4건 중 3건이 해소).
- **"방문해야 한다"는 판정도 확인해야 할 가설이다.** 원문 이미지가 있는지 묻지 않았을 뿐인
  경우가 있다.
- **찾으려던 것은 못 찾고, 찾을 생각 없던 것을 찾는다.** 이것이 정상이며,
  그때 조사 질문을 다시 쓴다.
- **강한 명제일수록 스스로 약점을 먼저 적는다.** 그래야 인용될 때 살아남는다.
