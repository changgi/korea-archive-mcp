부록 2직접 확인하는 방법

시연본은 설치 없이 파일을 열기만 하면 동작합니다. 인터넷 연결 없이도 시연 모드가 작동합니다.

1. 시연 모드 — 즉시 확인 girokitda/index.html 을 브라우저로 열기
화면의 예시 버튼을 누르면 각각 다른 이용자의 경로가 재생됩니다. 해외 소장·재산·신분·입양·지역 다섯 갈래를 다룹니다. 각 결과에는 그 내용이 실제 조사를 재현한 것인지 절차를 구성한 것인지 표시됩니다.
2. 실연동 모드 — 실제 오픈API 호출 [실연동] → [국내] 선택 → 요청주소와 인증키 입력
기관 오픈API는 요청주소와 파라미터가 기관마다 다르고 개편되기도 합니다. 그래서 주소를 코드에 고정하지 않고 이용자가 직접 넣도록 했습니다. 공공데이터포털에서 「나라기록물정보 서비스」 개발계정을 신청하면 상세화면에 요청주소와 예시가 표시됩니다. 응답 XML은 흔한 필드명을 폭넓게 훑어 제목·기관·번호를 추출하므로 기관이 달라도 동작합니다. 주소와 키는 브라우저에만 저장됩니다.
3. 배포하여 확인 정적 호스팅에 폴더째 올리면 공개 주소가 생성됩니다 (vercel.json 포함)
빌드 과정이 없습니다. 어떤 기록관이든 파일 하나만 받아 자기 데이터로 고쳐 쓸 수 있도록 단일 파일로 만들었습니다.
4. 해외 문서고 실연동 — 인증키 불필요 배포 후 [실연동] → [해외 · 영국 문서고] 선택
서버 프록시(api/overseas.js)가 영국 국립기록보관소를 대신 조회합니다. 표기 변형을 동시에 던진 뒤 유효한 것만 남기고 노이즈를 걸러내는 과정이 화면에 그대로 표시됩니다. 해당 기관 서버가 브라우저 직접 호출을 허용하지 않아 프록시를 두었으며, 코드가 제출물에 포함되어 있습니다.
5. 검사 파일 실행 — 41개 항목 npm install puppeteer → node test.js · node coverage.js
판단 규칙·응답 파싱·표기 판별·공동 발굴 대장·접근성·해외 검색 프록시를 자동 검사합니다. 계획서가 내건 네 약속을 기계적으로 검증합니다 — 근거가 없으면 답하지 않는다(여섯 가지 입력), 개인 신상은 저장하지 않는다(대장 저장 내용을 값으로 확인), 접근성은 기본값이다(글자·행간·키보드·초점·동작 최소화), 무엇이 실제이고 무엇이 구성인지 밝힌다(시나리오별 출처 표시). 규칙을 일부러 제거하거나 개인정보 항목을 추가하고 돌리면 해당 항목이 즉시 실패합니다. 또 산출물 정합 점검(consistency.js)으로 문서끼리 수치가 어긋나지 않는지 대조합니다. 실제로 처음 돌렸을 때 계획서에만 접근성 약속이 빠져 있는 것을 잡아냈습니다. 판단 범위 측정(coverage.js)으로는 반대 방향도 봅니다 — 국민이 쓸 법한 표현 35개에서 적중 100%, 헛보류 0건이고, 다루지 않는 영역 6개는 모두 올바로 보류합니다. 답하지 않는 안전장치와 제대로 답하는 범위를 함께 유지하기 위한 것입니다. GitHub Actions 설정이 포함되어 있어 코드가 바뀔 때마다 자동 실행됩니다.
6. 오답 방지 동작 — 직접 시험해 보세요 [막연하게 물어보기] 버튼 또는 "안녕하세요" 같은 모호한 질문 입력
근거가 부족하면 도장이 확인필요로 바뀌고, 답을 만들지 않습니다. 대신 가까운 갈래를 되묻고 담당기관을 안내합니다. 계획서에 적은 원칙이 화면에서 실제로 작동하는지 확인할 수 있는 항목입니다.

부록 7접근성 · 개인정보 · 연구 윤리

발굴 결과에는 개인의 신원이 포함될 수 있습니다. 본 과제는 다음 원칙을 따릅니다.

원칙내용
단정하지 않음동명이인 가능성이 있는 한 신원을 확정하지 않고, 대조가 필요한 항목을 함께 안내합니다.
시연 익명화공개 시연과 발표에는 익명 처리본을 사용합니다.
유족 확인개인 신원이 포함된 기록은 별도 검토 절차를 거쳐 제공합니다.
색 대비본문·보조 문구 11개 항목의 명암비를 실측해 WCAG AA(4.5:1, 큰 글씨 3:1)를 전부 충족하도록 조정했습니다. 밝은 배경용 보조색을 따로 두어 4.87:1 이상을 확보했습니다.
음성 입력재산·신분 기록 이용자는 상당수가 고령층입니다. 긴 문장 입력이 장벽이 되므로 말로도 받으며, 지원하지 않는 기기에서는 버튼이 나타나지 않습니다.
